# 월례회 · 행사 발표자료

이 저장소의 `index.html` 하나가 덱 전체다. CSS·JS가 모두 그 안에 인라인으로 들어 있고,
GitHub Pages가 브랜치를 그대로 서빙한다 (https://yonchelee.github.io/Oct_meeting/).
Team_townhall 덱에서 출발했고, 추첨 게임(Lucky Drop)은 빠졌으며 모션 레이어가 새로 들어갔다.

## 바꾸지 말아야 할 규칙

- **단일 파일.** 외부 CSS/JS 파일도, CDN도 쓰지 않는다. 사내망에서 바깥 호스트가 막히기
  때문에 라이브러리를 불러오는 순간 발표 당일 화면이 깨진다. 모션도 전부 손으로 쓴
  2D 캔버스와 CSS다. (예외: `media/` 안의 영상 파일 같은 같은 저장소 자산.)
- **저장소는 공개다.** 명단(이름·부서) 같은 사내 데이터는 절대 커밋하지 않는다.
- **사내 깃헙 임베드는 `pages.` 호스트로.** `github.sec.samsung.net`은 `X-Frame-Options`
  때문에 iframe에서 "연결이 거부됨"이 된다. 반드시 `pages.github.sec.samsung.net/...`.
- **한 섹션 = 제목 슬라이드 + 내용 슬라이드 2장.** 하단 점(dot)도 제목은 보통 점,
  내용은 `nav-dot--sub` 작은 점으로 짝을 맞춘다.
- 커밋 메시지·코드에 모델 이름을 넣지 않는다.

## 작업 순서

1. **무엇을 바꿀지 확정한다.** 행사마다 바뀌는 건 대개 섹션 목록(주제·순서),
   임베드 주소, 영상, 인트로 문구다.
2. **`index.html`을 고친다.** 구조와 수정 지점은 `references/deck-anatomy.md`,
   모션은 `references/motion.md`를 먼저 읽는다. 짧은 문자열은 여러 곳에 걸리므로
   치환 전에 `count == 1`을 확인할 것.
3. **검증한다.** 눈으로 보지 말고 돌려본다 — `references/verify.md`.
   문법 검사 + 브라우저 프로브(전 슬라이드 이동, 모션 동작·휴면, 콘솔 에러 0)는 매번.
4. **커밋 & 푸시** → 지정 브랜치.
5. **배포를 확인한다.** `scripts/watch-deploy.sh` 로 라이브 페이지가 로컬 파일과
   바이트 단위로 같아질 때까지 기다린 뒤에 "배포 완료"라고 말한다.

## 실수하기 쉬운 곳

- 슬라이드를 지우면 **하단 점, 리모컨 목록, 영상 훅**이 같이 따라가야 한다.
- `render()` 안의 `slides[current].id === '...'` 분기가 id에 의존한다
  (`intro` 파티클 타이틀, `closing` 영상, `video`/`video-content` 임베드 영상).
- 제목(`.headline`)은 스크립트가 글자 단위 `<span class="ch">`로 쪼갠다. 마크업에는
  평범한 텍스트로 쓰고, `reveal` 클래스를 붙이지 않는다.
- 캐러셀의 `render();` 호출은 스크립트 **맨 끝 한 줄**이다.
- 헤드리스 검증 환경은 GPU가 없어 4~8fps다. 모션이 "되는지"만 보고 부드러움은 사내 PC에서 본다.
- 헤드리스 Chromium에는 H.264 디코더가 없다. 로컬 mp4 재생은 사내 PC에서 확인한다.
